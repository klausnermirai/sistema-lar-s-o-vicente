# Instruções do Usuário

## Fluxo de Trabalho
- Sempre que o usuário solicitar algo, devo primeiro traçar um planejamento do que entendi.
- Solicitar a aprovação do usuário para o planejamento.
- Sempre faça uma análise de desempenho da solicitação. Se a função solicitada não puder ter um bom desempenho ou não for viável, informe o usuário indicando, por exemplo: "A função solicitada pode não ter o desempenho esperado ou ser inviável devido a...".
- Sempre faça uma análise de risco da solicitação. Se a nova alteração colocar em risco algo na estrutura já criada (especialmente frontend, backend ou banco de dados), retorne ao usuário alertando: "A solicitação pode alterar significativamente o sistema colocando em risco...".
- Somente após a aprovação de todo esse cenário, iniciar a implementação das mudanças.
